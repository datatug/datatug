## Journey and selected delivery shape

A user supplies a reviewed native-table profile and a scalar structured query, chooses their own execution identity/project, sees the policy-effective query and dry-run estimate, approves its exact positive bytes cap, then reads pages from one job. Go ships in the real DataTug CLI and a local service harness; JavaScript ships browser-direct in DataTug. Browsing requires neither signup nor cloud execution. Browser Run preserves its draft through explicit DataTug signup/sign-in and separate GIS consent. Both real-runtime gates remain mandatory.

Use a new `datatug query bigquery` command group in the existing CLI. Do not add a fake BigQuery `dal.DB` to `dbcopy`, reuse an HTTP snapshot fallback, or overload `--project` (which means a DataTug project). Commands:

- `preview --source-profile <file> --file <dtql.yaml> --execution-project <id> --auth adc --maximum-bytes-billed <decimal> [policy flags] --preview-out <private-file>` validates, applies policies, observes metadata, dry-runs and prints the effective query/parameters plus estimate/cap/bounds and approval digest. No paid job.
- `run` takes the same source/query/context flags plus mandatory `--preview <private-file> --approve-digest <digest> --receipt-out <private-file>`. It repeats policy preparation and metadata/dry-run, checks the digest, then rechecks metadata immediately before submitting once. It streams the first result page as the normalized JSON envelope. There is no `--yes` that bypasses an absent/mismatched digest.
- `page --receipt <private-file> --cursor <opaque> --auth adc` reads the next same-job page. `status` and optional `cancel` use the receipt and same authenticated execution principal. No command reconstructs or reruns expired results. `cancel` requires the separately enabled cancel-capable credentials; lack of capability returns an actionable error. Ctrl-C means local stop.

Policy flags reuse `--as/--role/--group/--var/--policy/--policies-dir/--no-policies` and their existing loading/denial semantics. Initial output is `--format json` only, with schema plus exact typed cells and receipt/cursor; reject other formats rather than using the current keyed-row collector. Query and profile files are bounded to 256 KiB; strict DTQL parsing and the bounded subset below apply. Existing saved `query run --project ... --query ...` continues unchanged: it loads QueryDef and dispatches HTTP/SQL/DTQL through `secureread`, then may perform federated lookups. It is not a safe first BigQuery injection point. The concrete new command is the selected real consumer, not an example pretending to be it.

A valid input shape, verified against DALgo v0.89.6's DTQL parser:

```yaml
from: {name: sample}
columns: [{field: word}, {field: word_count}]
where: {op: ">=", left: {field: word_count}, right: {value: "10"}}
orderBy: [{field: word}]
limit: 100
```

The logical collection `sample` maps only through the supplied reviewed descriptor. Source identifiers never come from the DTQL field text or the job project. Exact INT64/decimal parameters must be quoted strings; reject YAML-decoded numeric inputs for these types, including seemingly safe numbers. `--var` bindings for exact numeric types follow the same rule.

## Policy bridge and exact Go APIs

Existing facts: `dal.QueryExecutor` has `ExecuteQueryToRecordsReader(context.Context, dal.Query)` and `ExecuteQueryToRecordsetReader(context.Context, dal.Query, ...recordset.Option)`. `dal.RecordsetReader` adds `Recordset()` and `Next() (recordset.Row, recordset.Recordset, error)` to `Cursor()/Close()`. `access.SecureReadSession` accepts `dal.ReadSession`, applies row residuals and explicit-column field projection in its recordset method, and can invoke a generic recursive engine for nested queries. Current CLI `accesspolicies.Run` only returns a keyed RecordsReader. None of those facts implies a new core API is needed.

Add a CLI-owned `accesspolicies.PrepareRecordset(ctx, query, options, validate)` helper returning `{Context, Query, Lines}`. These names are proposed new consumer APIs. Factor/reuse the preparation in `run.go`: explicit no-policy requirement, principal/variables context, parameter substitution, Explain lines, alias refusal and hidden-reference checks. Before entering SecureReadSession, call the adapter's pure whole-query guard; it rejects every unsupported AST shape before any generic recursion can occur. For policies, invoke SecureReadSession around a private capture-only ReadSession. Its Get/GetMulti/Exists and keyed-query method return ErrNotSupported; its recordset method captures exactly one rewritten query and returns an internal sentinel. The helper recognizes only that sentinel, rejects zero/multiple captures, then guards the resulting query again. The capture session has no transport or DB. With explicit unrestricted mode, prepare directly without SecureReadSession. Do not rely on Explain as authorization.

Preview and run use the returned policy-effective query. Before submit, repeat preparation from the original bounded input and current policy files, bind the policy-file digest, selected app principal/variables and effective plan into approval, and reject any change. Page/status/cancel reload the original protected context privately and reauthorize it: a changed policy/principal fingerprint refuses result access, even though the Google job already exists. A cursor is never a policy grant. This keeps DataTug policy principal separate from Google execution principal.

New driver API (proposed, not already committed): `NewClient(Config)`, `ValidateQuery(dal.Query) error`, `Compile(SourceProfile, dal.Query) (ReadPlan,error)`, `Observe(ctx, SourceProfile) (Observation,error)`, `Preview(ctx, ReadPlan, Execution, Bounds) (Preview,error)`, `Approve(Preview,digest) (Approval,error)`, `Execute(ctx, Approval) (*Run,error)`, `Resume(ctx, Receipt,Cursor) (*Run,error)`, `Status(ctx, JobRef) (JobStatus,error)`, `CancelJob(ctx, JobRef) (CancelResult,error)`. Approvals are immutable adapter-created objects, not trusted caller booleans. Config takes injected authenticated transport/identity provider and a private ledger; never a descriptor-provided API endpoint.

`Run` implements `dal.RecordsetReader` and exposes adapter-owned `Schema()`, `Receipt()` and `NextPage()` for typed JSON consumers. A driver `Executor` bound to one approved plan implements `dal.QueryExecutor`: recordset execution compares the entire incoming compiled plan to that approval and consumes it once; keyed execution returns ErrNotSupported. Exported metadata preserves full warehouse schema through the adapter; source type also populates `recordset.ColDbType`. No invented business key. Recordset storage remains page-bounded: rows belong to the returned page recordset; callers retaining data own its memory. `NextPage` and row iteration cannot be mixed on the same Run.

## Shared wire contract, version 1

The JSON contract is adapter-owned, not a new source registry or core interface. All objects reject unknown fields on input. Hashes are SHA-256 over deterministic UTF-8 canonical JSON (sorted object keys, original array order, no whitespace, exact decimal strings). No floating values participate in hashes: FLOAT64 parameter text is normalized first. Copy/freeze inputs before hashing. The corpus supplies exact canonical bytes/digests so independent encoders cannot drift.

- `SourceProfile`: `{version:1, sourceId, descriptorDigest, logicalCollection, sourceProject, datasetId, tableId, location, schema, publisherReviewRef, rightsReviewRef, use:"connection-test"|"admitted"}`. Rights refs/status are existing specialist outputs, never fabricated here. An explicit connection-test profile cannot become an admitted public source. Exact identifiers are restricted ASCII BigQuery project IDs and `[A-Za-z_][A-Za-z0-9_]*` dataset/table/column names; reject decorators, wildcards, dots in column names and arbitrary SQL. This narrower identifier profile is intentional.
- `ReadPlan`: `{version:1, sourceDigest, projection:[column], where:Predicate|null, order:[{column,direction:"ASC"|"DESC"}], limit, parameters:[{name,type,value}], sql, digest}`. `sql` is produced internally only. One root logical collection; 1–128 distinct explicit scalar columns; no aliases, star, computed expressions, joins, aggregate/group/having, subqueries, offset, DALgo StartFrom/StartAfter, collection groups or nested paths. Any unknown AST node fails. Predicate supports bounded AND/OR groups, scalar field-to-typed-value `= != < <= > >=`, IS NULL/IS NOT NULL, and IN against typed scalar arrays (0–1000 elements, empty IN compiles to FALSE); no NULL in IN. Up to 128 predicate nodes, depth 8; up to 16 simple order columns. Null comparison uses explicit null tests, not `= NULL`. Only ordered scalar types permit inequalities/order; JSON/BYTES permit projection only; BOOL supports equality/null. All data values become named parameters; only validated descriptor identifiers and bounded integer LIMIT are rendered.
- `Execution`: `{jobProject, principal:{kind:"google-user"|"workload", subject, generation}, maximumBytesBilled, sessionBudgetBytes}`. Positive cap and budget are base-10 integer strings <= 9223372036854775807. No source/credential/quota-project fallback. Token/grants/expiry provider is runtime-only and absent from JSON.
- `Bounds`: defaults/hard maxima `pageSize=100/1000`, `maxRows=1000/10000`, `maxPages=100/100`, `responseBytes=4MiB/10MiB`, `totalResponseBytes=32MiB/32MiB`, `wallMs=120000/120000`, `httpMs=15000/15000`, `concurrency=1`. All metadata, status, retries and result bodies debit cumulative decompressed bytes; bound parse depth (32), schema fields (1024), and scalar text (1MiB). Exceeding any limit preserves a truthful partial receipt and stops locally; does not imply server cancellation. Requested smaller bounds are binding, not increased automatically.
- `Observation`: exact table reference, dataset location, type/config profile, schema (name/type/mode/fields/precision/scale), schema/config digests, observedAt, optional etag/lastModified. Separate volatile timestamps/counts from the execution-relevant digest; an etag alone is not a content pin.
- `Preview`: plan plus observation digest, policy-context digest when applicable, principal generation, project/location, cap/budget/bounds, exact estimated bytes, creation/expiry time (5 minutes), and approvalDigest. The content digest excludes observation times, etag/lastModified and preview timestamps; the persisted preview separately holds its 5-minute validity and single-use nonce. Run loads that original preview, checks expiry/nonce, re-prepares/re-observes/re-estimates, and compares the binding payload before approval. Missing/invalid estimate, dry-run error or estimate exceeding cap refuses execution. Any relevant change invalidates it. Budget reservations are not yet consumed for a dry run.
- `Receipt`: version, runId, approvalDigest, source/observation/schema digests, principal binding, job reference when known, state, timestamps, bounds/counters, scan/billing/cache fields with presence retained, warnings/reason codes, residualSourceReplacementRace=true. Private resume state additionally holds approved input/context and cursor ledger; it may contain query values and must be 0600/local-private, never telemetry/public evidence. Sanitized public receipts omit values/tokens/account labels.
- `JobRef`: required `{projectId,jobId,location}`; returned fields must match the approved job project/location. Require a nonempty jobId on execution (`JOB_CREATION_REQUIRED`); source project remains independent.
- `Cursor`: opaque versioned encoding of runId/jobRef/planDigest/schemaDigest/principal generation, current page request token (null means GET startIndex=0), fixed pageSize, consumed offset, page-content digest, ordinal/counters and ledger reference. Persist cursor only after rows are delivered. Partial-page resume refetches the same page, verifies its digest and skips exactly consumed rows; never publish the next token early. Boundary cursor uses the next token with offset zero. Schema is retained from the initial successful schema-bearing response; later omitted schema is allowed, supplied mismatch fails. Reject token cycles, job/context mismatch and expired results. Counters/budget are checked against the trusted per-run ledger, not caller-edited cursor totals.

Rows are ordered arrays of `Cell={type, value}` where `value:null` is SQL NULL; no row key. Schema precedes even empty results. INT64/NUMERIC/BIGNUMERIC use validated exact strings and preserve numeric value/precision; canonical decimal normalization removes redundant leading/trailing zeros and normalizes negative zero to `0` (never exponent notation). INT64 range is signed 64-bit; decimal precision/scale/range must match the Google type and supplied field constraints. FLOAT64 accepts finite values only, normalized to round-trippable decimal text in shared JSON; nonfinite returns unsupported_value. BOOL outputs boolean after strict `"true"/"false"` decoding. STRING remains string; BYTES is tagged valid canonical base64. DATE/TIME/DATETIME are validated calendar strings without invented timezone. Request `formatOptions.useInt64Timestamp=true` consistently on Query and GetQueryResults; TIMESTAMP uses exact signed epoch-microseconds strings, never JS Date or floating seconds. JSON wire value is preserved as valid serialized JSON text: `{"type":"JSON","value":"null"}` differs from SQL NULL. ARRAY/STRUCT/RECORD, GEOGRAPHY, INTERVAL, RANGE and any unknown types stay discoverable, nonselectable with reason. Required/nullability violations and invalid wire types fail; they never coerce to NULL.

## Raw HTTP, metadata and job protocol

M1: stream-bound/decompress-bound every response before parse. Reject duplicate JSON object keys, trailing values, malformed UTF-8, excessive depth and wrong shape. Preserve presence through Go `json.RawMessage` (or equivalent lossless scanner) and JS own-property checks after the duplicate-key scan. Validate schema before rows; every `f` has exactly the projected width; each cell is an object with exactly one `v`; `v:null` is SQL NULL, missing `v` is malformed. Non-null scalar `v` must have its documented string wire type, not number/object/array. Decode nothing from generated TableCell.V until these checks pass. The Go response RoundTripper validates bounded raw bytes and replays those validated bytes to generated decoding; copy a validated JobRef to the run ledger before row validation can fail. If job identity cannot be established after submission, retain the reservation with submission_unknown. The actual raw bytes go through both runtimes' production transport/decoder in tests.

M2: before dry run and again immediately before execution, `datasets.get(sourceProject,dataset)` must return matching identity and location; `tables.get` must match all three identifiers, schema and the reviewed native `TABLE` profile. Reject VIEW/EXTERNAL/MATERIALIZED_VIEW/SNAPSHOT/CLONE/unknown type and any present non-null view/materializedView/externalDataConfiguration/biglakeConfiguration/snapshotDefinition/cloneDefinition, conflicting config, unknown execution configuration or malformed schema. Native time/range partitioning, clustering and requirePartitionFilter are supported configuration only when structurally validated and bound into the observation. Maintain an explicit raw top-level/config-field allowlist pinned to the SDK discovery schema; known nonexecution metadata/statistics may be ignored for approval comparison, unknown fields fail closed until classified. No projection of only a few metadata fields that could hide an unsupported configuration. Relevant type/config/schema/location changes invalidate approval and produce zero execution submissions. Etags/timestamps are observations; there remains a non-atomic upstream replacement race after recheck. Only reviewed trusted publishers qualify; no immutable/adversarial-source guarantee is claimed.

Transport origin is fixed `https://bigquery.googleapis.com/bigquery/v2/`; redirects refused. Go SDK is constructed with an explicit authenticated HTTP client and a discard logger (`option.WithLogger`), because generated debug logging includes request/response bodies. Do not expose mutable Service/BasePath outside the adapter. SDK default scopes/credentials are not invoked accidentally; specifying a client does not grant new scopes. Transport must not retry POST submissions; a bounded in-memory attempt gate enforces one underlying dispatch per execution even with custom middleware. No idempotency header or replayable request configuration that turns Go HTTP retries into a second submission. GET metadata/page/status retries: at most 3 attempts, bounded exponential backoff and Retry-After, all charged to wall/byte limits.

Dry run and execution call Jobs.Query explicitly; never Jobs.Insert or high-level Query.Read. Send explicit location, GoogleSQL false pointer, NAMED parameters, mandatory exact cap, maxResults, 1000ms initial wait, required-job mode and integer-microsecond timestamp format. Execution sends false dryRun explicitly; jobTimeoutMs may equal wall bound but remains best effort, not a cost control. Missing cap/overflow or mutated SQL/parameters refuses before network. SDK requests encode positive caps as int64 JSON strings. Typed NULL parameter uses declared type and explicit `parameterValue.value:null`; empty strings are force-sent, never accidentally omitted by generated omitempty. Parameters and requests have byte-level parity fixtures.

State machine: draft → previewed → approved → reserved → submitting → running → completed/failed/cancelled. Submission transport loss transitions to submission_unknown, never automatically retries. Persist a job receipt immediately once validated. Local Stop/Close sets localStopped and aborts local I/O, leaving job state running/unknown. Cancel uses a fresh <=15s control context, originating project/job/location/principal, and only the separately authorized broader scope; it sets cancel_requested, then GET status establishes terminal cancelled, completed-before-cancel, failed or unknown. A nonempty warnings/errors list is not a terminal verdict; Jobs.Get status.state DONE plus errorResult controls failure, and ambiguous stopped reasons are not invented cancellation receipts.

Reserve the job cap atomically in a per-execution-principal/project session ledger before submission; approved object is one-shot. Concurrent run commands share a locked private ledger, browser tabs use one coordinated ledger. Known completion reconciles to observed billed bytes when available; unknown/submitting/partial/cancel-pending jobs retain full reservation. Missing billing stats retain it; no zero inference. Ledger survives deliberate resume, contains no OAuth token, and does not claim to enforce Google-project-wide budgets or defend a malicious owner. Do not start a new budget session silently to evade an outstanding reservation.

Stable errors: invalid_input, unsupported_query, unsupported_type, unsupported_value, policy_denied, no_policies, auth_required, auth_expired, scope_missing, source_ineligible, source_changed, approval_required, approval_changed, estimate_missing, cap_exceeded, budget_exhausted, response_limit, malformed_wire, schema_changed, cursor_invalid, result_expired, submission_unknown, local_stopped, remote_failed, cancellation_unknown. Include sanitized provider reason/status and known JobRef separately; never SQL, values, tokens or raw service bodies in errors/logs. Exit policy denial remains 5, usage 2, provider/execution 4; unknown submission must print its precise state rather than imply safe retry.

## Identity, browser and service ownership

Browser GIS requests bigquery.readonly + openid; email is optional for display. Fetch fixed Google discovery metadata and accept its UserInfo endpoint only under the expected Google HTTPS origin/path allowlist; currently `https://openidconnect.googleapis.com/v1/userinfo`. Call it with the exact same access token used for BigQuery. Bind stable nonempty sub; missing email is permitted; missing sub/required grants refuses. Display DataTug/Firebase identity and execution identity separately; preserve explicit account choice, no automatic link. Every token/account/grant change revalidates identity, advances generation and invalidates pending approvals. Reconnection may explicitly rebind an existing job only after the same stable subject is verified; no new submission. Clear memory-only tokens on disconnect/signout; no persistent token storage. Broader bigquery cancellation consent is optional and truthful about its scope. No cloud-platform shortcut.

CLI `--auth adc` is explicit opt-in; the application auth factory obtains a user-controlled token source without choosing a project from ADC. For Google-user credentials, verify the principal by same-token UserInfo under existing identity grants; ADC scope options cannot manufacture a missing grant. Missing identity/capability returns setup guidance, not a fabricated --principal label. The standalone service harness accepts an operator-injected trusted identity/token provider; workload identity subject comes from that provider's authoritative configuration/attestation, not caller request JSON. Google-user and workload principal kinds are distinct; a workload need not pretend to have an OIDC user sub. No service-account keys in source/manifests. Credential selection/configuration and OAuth client setup are not performed in A0.

The local server harness lives under `examples/server` in the Go driver. Export a handler factory with injected client/profile/policy-prepared plan, and a runnable example using an operator-controlled provider; test via httptest without real ports. Its runtime server, if deliberately launched for the live gate, binds loopback only with a documented owner/shutdown and rejects cross-origin/untrusted browser requests. It offers preview/execute/page/status/cancel for a fixed injected source and cost principal, never a public shared spender, and never mounts a fake OVDB query endpoint. Actual server-harness and real CLI acceptance are both recorded.
