## Separate serving identity and source fidelity

Add optional `Storage.SQLite *SQLiteOptions` with `storage.sqlite.record_keys` mapping native logical collections to one declared TEXT serving column. Whole-option absence preserves legacy `id` behavior. When configured, require complete coverage, exact spelling, nonempty names, declared string fields, known collections, the actual physical column, no NULL/empty/duplicate values and a matching unique index. Reject other engines and ambiguous logical/quoted aliases. Keep quoting in DALgo. Configured identity is authoritative across keyed, ordinary, structured and snapshot reads; missing DAL key fails rather than falling back to native `data.id`.

The optional `storage.sqlite.busy_timeout` has explicit presence, integer-millisecond validation from zero through five seconds, omission preserving the historical default. W1 emits `0s` on both driver and metadata handles with no automatic lock retry. The lock becomes a visible bounded error, subject to actual cancellation/cleanup proof.

Cloud opts into `separate-id/1` independently of existing `recordKeyFormat` natural/legacy. Choose `__ovdb_record_id`, then the smallest positive suffix on case-insensitive collision; allocate the generated index similarly against every actual schema object. Existing key-format functions produce unique TEXT values. Composite/keyless behavior stays deterministic for the pinned snapshot. All six demos retain their previous adapter/key format.

Keep every native field, including ROR `organizations.id`, its spelling/type/raw value, native indexes, FKs and views. The helper appears only in derived serving SQLite/YAML; it is not a ModelSpec identifier or semantic binding. SELECT-all may expose it; selected projection may omit it while Record.Key still works. Compare native table/index/FK/view metadata without broad exclusions, subtract only the exact generated objects, and stream a typed-row digest over original columns in deterministic source-key/rowid order before/after. Preserve NULL, empty and BLOB bytes. Physical FK checks concern only source-declared constraints; do not fabricate targets for semantic exceptions.

Record smoke uses the API's authoritative escaped `key`, encoded exactly once, and compares record key/data with query results. Cover slash, percent, space, quotes and punctuation, projected keys, native id/ID and helper collisions, empty/keyless/composite tables and all legacy demos.

DALgo read helpers reuse the existing context-aware `executeQueryFunc`; DB and transaction Get/GetMulti/Exists call QueryContext. Check cancellation before each group, propagate cancellation/deadline and scan/rows.Err errors, annotate unfinished records and stop batches. Do not convert cancellation into not-found/false or swallow canceled singleton groups. Close rows on every path and route worker errors into transaction rollback. Keep the unrelated contextless setter alias; adapt only the inserter's shared existence probe to QueryContext, without context.Background adapters or a general write rewrite.

## Explicit guarded execution and truthful discovery

Use ordinary POST `/v1/databases/{id}/dtql`, explicit limit at most 1,000, bound IN/equality filters on admitted native/bridge fields and server-owned ascending unique-key ordering. Client orderBy is refused with 400 `ordering_unsupported`, rather than silently overwritten. A structured-query ordering wrapper preserves other fields and truthful String. `server.WithDatabaseReadProfiles(map[string]ReadProfile)` derives from checked inventory and validates immutable SQLite plus complete key map at construction. No client key registry, server run ledger or W1 snapshot spool is introduced.

The `bounded-immutable/1` profile rejects snapshot-page headers before capture and rejects relational/cross-database/derived/subquery execution referencing W1 after auth/target resolution and before SQL/field discovery, using complete resolved-source inventory rather than text search. Ordinary pages and required keyed/batch/Exists routes use incoming context with at most ten seconds; legacy routes, snapshot constants and global query defaults retain their prior behavior.

Wire request/response pins are `OVDB-Provider-Revision` (40 hex), `OVDB-Source-SHA256`, `OVDB-Serving-SHA256` and `OVDB-Manifest-SHA256` (64 hex). First read per database requires provider/source and may omit serving/manifest only together; serialize first reads and return all four. Continuation and saved scenarios send all four. Invalid/missing pins fail 400; mismatch fails 409 `snapshot_mismatch` before SQL. Compare the verified immutable mounted instance/manifest under a read lease or startup snapshot, not a mutable pathname. Validate response pins and exact 200 before accepting rows; match source repository/route to admitted Directory coordinates. Expiry/mismatch requires a fresh explicit run and revision acknowledgement.

POST and keyed GET responses use no-store, enforced at header write despite downstream overwrites. Forward/expose all four headers through Worker and additive per-instance CORS settings, preserve Vary and exact configured HTTPS DataTug origins, pass request.signal upstream and keep redirects refused. Browser stream-reads with remaining-byte bounds before JSON.parse.

One existing app federation run owns a monotonic ten-second deadline and shared AbortController/counters across providers, pages, stages, retries, errors and cached inputs: 1,000 user rows, 50 distinct ROR IDs or 100 place IDs, 5,000 intermediate rows, 5,000 final results, 5 MiB decoded network and independently 5 MiB materialized output. Page size respects remaining allowance. No request begins after exhaustion. Further pages require explicit user action; waiting does not reset an old run's deadline. No automatic drain, sentinel/refetch or idle/reopen query; a full page or 5,000-result boundary remains possibly-more unless independently proven exhaustive. Browser metadata retains the aggregate 2 MiB ceiling. Server ordinary limits remain ten seconds/1,000 rows/8 MiB per query, separate from the shared app budget. Prompt cancellation must be demonstrated through the actual browser/Worker/service/driver path.

One configured `relationalRefusal`/shared predicate drives relational execution and joins/aggregation discovery. Both candidate and final W1 advertise joins/aggregation=false. Ordinary advertisement independently combines CanQuery, configured ordinary-read allowance and checked provider/descriptor published-query availability. Candidate W1 has query/dtql=false and no endpoint/format; explicitly pinned candidate smoke may establish proof. Final published W1 has read/query/dtql=true, write/joins/aggregation=false and the actual ordinary endpoint/format. Checked descriptor mismatches fail preparation/startup. Preserve legacy behavior and global feature blocks. Both W1 states have empty human QueryURL using the existing HTML conditional, retaining metadata/schema links. No pin enters a URL or new query UI.
